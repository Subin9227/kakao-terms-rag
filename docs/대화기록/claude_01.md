약관 원문을 정제했습니다. PDF에서 뽑은 통합 약관이 줄바꿈으로 어절 중간을 끊고 있었습니다.

```
'... 세부지침에 따\n릅니다.'   →  기존 파일은 '따 릅니다' 로 저장돼 있었음
'... 2시간 이 상 복구가'
'... 존속하게 됩니 다'
```

되붙이기 판단은 사전으로 했습니다. 줄 끝 어절 + 줄 첫 어절을 공백 없이 이었을 때 나머지
약관 어디에도 없는 말이 되면 원래 띄어쓰기였던 것이고, 실제로 쓰이는 말이 되면 PDF가
어절 중간을 자른 것입니다. `따`+`릅니다` → `따릅니다`(사전에 있음) → 붙인다.
`및`+`규칙` → `및규칙`(사전에 없음) → 띄운다.

음절 bigram이 이득을 만들고, **조사 제거는 오히려 깎습니다**(0.8380 → 0.8333, top4 18/18 → 17/18).

1위가 아닌 문항을 보니 원인이 명확했습니다.

```
H09 rank=2 gold=[('카카오계정 약관', 14)]  got=[('카카오 통합 약관', 20), ('카카오계정 약관', 14), ...]

```

H09는 질문이 "카카오계정 약관에서…"로 시작하는데 다른 약관을 1위로 뽑았습니다.
문서명 부스트를 넣었습니다. 질문이 약관 이름 전체를 포함하면(가장 긴 이름 우선) 그 약관
조항에 `boost × (max − min)` 을 가산합니다. 자르지 않고 가산만 하는 이유는, P02처럼 정답이
세 문서에 나란히 있는 문항이 실제로 있기 때문입니다.


**검증 MRR 0.8380 → 0.9074, 공개는 1.0 유지.** 고원의 가장 작은 값인 0.5를 씁니다.

지점이라 dense 검색의 존재 이유가 여기 있습니다.
